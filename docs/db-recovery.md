# Runtime database recovery
Do not delete pgdata. Stop radius and api, build latest backend/radius, run docker compose run --rm migrate (owner credentials; provisions restricted roles), and only after exit zero recreate api and radius with docker compose up -d --force-recreate migrate api radius. Keep ZRADIUS_SECRET_KEY and original POSTGRES_PASSWORD unchanged. POSTGRES_PASSWORD does not reset the password of an existing PostgreSQL volume. Runtime password must match .env and container environment. To inspect runtime connection without printing credentials: docker compose run --rm --no-deps --entrypoint sh radius -c 'PGPASSWORD="$RADIUS_DB_PASSWORD" psql -X -w -h postgres -U zradius_runtime -d radius -c "SELECT current_user,current_database()"' . Startup now reports connection errors or missing schema/permissions instead of suppressing stderr. A missing migrate container can indicate stale compose deployment; actual root cause requires migration output. Healthcheck escapes Compose interpolation so the secret is expanded inside the container, not by the host. No database data removed. Runtime not verified.
