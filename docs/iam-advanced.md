# IAM management
Migration 0005 adds a public UUID per session, independent of bearer token hash. Admin can create users, change role, reset password, disable and revoke individual sessions from the console. Personal password change requires current password and revokes all sessions. Role changes also revoke all sessions. Login locks the user row to serialize credential checks against password reset/disable. Last enabled administrator cannot be demoted. Non-admin access now uses explicit resource allowlist, with only operator session rate/disconnect writes. Existing read permissions remain broad within listed resources; not object-level or custom-role RBAC. UI hides IAM admin navigation from non-admin users, but other legacy controls may remain visible and are rejected server-side. MFA, service accounts, user-configurable permissions and JWT are not implemented. No password recovery or forced password change after admin reset. CI and runtime verification pending.
