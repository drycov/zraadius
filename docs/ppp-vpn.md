# L2TP / PPP VPN management (experimental)
Migration 0013 adds PPP profile references and dedicated L2TP users, each bound to one registered MikroTik NAS with l2tp service. Static IPv4 unique per NAS (including disabled users); otherwise an explicitly named local RouterOS pool is required. Profile names and pools must already exist on NAS. PAP uses salted SHA-512, MS-CHAPv2 uses NT hash (password-equivalent, protect DB and backups). CHAP and MS-CHAPv1 reject. No plaintext password storage for new L2TP users; API must use TLS/VPN. The l2tp realm no longer falls back to generic radcheck users. PPPoE stays unchanged. Do not deploy this change against an existing production L2TP realm until all accounts are explicitly migrated. RouterOS service=ppp covers multiple PPP protocols; realm alone is not proof of L2TP tunnel type. Use dedicated NAS or ensure all PPP traffic on the selected RADIUS entry is intended for this policy. Accounting uses existing radacct; no VPN-specific session enforcement yet. No cross-NAS address collision check, pool overlap detection, profile edit/delete, legacy import, or active session termination. No actual account data imported. Validate config and PAP/MSCHAPv2 on test NAS before switching. Unit tests added, not executed here.
