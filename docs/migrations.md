# Database migrations
The one-shot migrate service runs alembic upgrade head after PostgreSQL readiness and before API and RADIUS start. Existing ZRADIUS development databases are adopted by executing a frozen idempotent baseline once, then validating selected required columns. This is not a migration from arbitrary third-party FreeRADIUS schemas. No automatic stamp or destructive downgrade. The baseline SQL is immutable; add new revisions instead of editing it. A PostgreSQL transaction-scoped advisory lock serializes migrations, and failures roll back transactional DDL. The API checks the expected revision at startup and readiness, never runs DDL. The original schema.sql is retained as a historical reference only. DB role separation remains outstanding. Before upgrading an existing system, take a verified pg_dump backup and schedule a maintenance window. For a manual upgrade: docker compose stop api radius; docker compose build api migrate radius; docker compose run --rm migrate; docker compose up -d. Do not remove the PostgreSQL volume. CI checks repeated upgrade and revision; full legacy upgrade testing remains outstanding.
