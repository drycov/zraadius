# Legacy identity migration

Personal administrator only. GET /identities/legacy-candidates lists independent Device AAA, L2TP or IAM users without hashes. POST /identities/legacy-migrate accepts service, user_id, preview (default true), and a new password on apply. Preview checks exact-name conflicts; apply rechecks under locks. No automatic merging. Existing service row ID, grants, group membership, profile, static address and local enabled state are retained. The transaction temporarily renames the legacy row to satisfy the immediate namespace trigger, then restores the original login with the new identity link and clears local hashes. Other transactions do not see the intermediate rename. Global identity starts disabled; explicitly enable after verification. Existing network sessions are not terminated. IAM migration preserves account ID, role, local enabled state and enrolled MFA/recovery codes, clears pending MFA enrollment, replaces the independent password hash with an unusable random-password hash and revokes sessions. The last active administrator cannot be migrated while no other active administrator exists. Generic radcheck, EAP and vouchers are not migrated. No migration file needed; runtime and build verification pending.

## EAP migration

Dedicated legacy-eap-candidates and legacy-eap-migrate endpoints accept username and use explicit NAS grants. One NAS per EAP service, exclusive service classification, no conflicting legacy attributes, and new password are required. VLAN, username and local enabled state are preserved; central identity is disabled. Multi-NAS same-service and unassigned users require manual review. Generic PPPoE/radcheck migration remains unsupported because arbitrary RADIUS checks/replies/group policies cannot be represented losslessly by the unified PPPoE model.
